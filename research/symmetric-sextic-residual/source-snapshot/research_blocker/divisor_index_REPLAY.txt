The index is enabled by default. --divisor-index 0 disables it while retaining
separate subphase profiling. Existing --threads, --resume-state, --seconds,
--pairs and checkpoint arguments are unchanged. The existing560-byte native
metadata ABI is preserved. The index is rebuilt from the active heads each
symbolic phase and is not serialized into native state. Restoring the actual
pending pair queue remains unchanged. No target computation was run by the
index implementation task, and no target speedup is claimed in these receipts.

Why this addresses the measured lookup
--------------------------------------
The independent real-batch profile found43.0777 seconds in divisor lookup and
43.4851 seconds in row materialization. There were835256 lookup calls and about
2.94billion leading-position visits; the short-mask filter rejected very few.
Those observations motivate a different exact lookup, but do not themselves
measure this variant. Even eliminating lookup entirely would leave the measured
materialization and other costs. The mathematical finite-algebra task remains
unfinished until its computation and subsequent verification complete.

Algorithm and exactness
-----------------------
For each eligible symbolic phase, build an open-addressed hash table of the
current active leading monomials. A table entry holds its native additive hash
and its position in the ordered lmps list. The native exponent vectors already
stored in the basis are used for full comparisons, so no duplicate exponent
snapshot is allocated.

A query x^e has exactly the product of(e_i+1) monomial divisors. If that product
is at most256, enumerate every exponent vector d with0<=d_i<=e_i. A sparse
odometer touches only the nonzero coordinates of e. Its native hash is updated
incrementally. Ordinary DRL stores total degree in slot0, so the additive weight
of coordinate j is rn[j]+rn[0]; the degree slot is adjusted on every increment
and carry. This avoids constructing a new38-coordinate key for every divisor.

Each candidate probes the active-head table. A hash match is accepted only after
checking the full native exponent vector, including its degree slot. Every
matching active head is considered, and the MINIMUM lmps position is retained.
An early exit is allowed only after finding position0. Therefore the selected
reducer is exactly the first divisor the original ordered scan would choose,
independently of the enumeration order or head-hash collisions. Duplicate heads
also select their first list position. The final selected head is checked again
for active status and full divisibility before forming the multiplier.

The bounded enumeration is exhaustive: the odometer ranges independently from0
to e_i in each supported coordinate. Every divisor appears once. A true divisor
has the same additive hash as its corresponding enumerated vector; all hash
collisions are disambiguated by full equality. Linear probing continues until an
empty table slot. Load is at most one half. Table exhaustion or failed runtime
checks fall back to the original exact scan rather than omit a reducer.

The original scan is used when the divisor product exceeds256, for block/lex
orders, signatures, tracing, final reduction and other unsupported modes. The
product calculation saturates safely at UINT64_MAX and reports any overflow.
The supported fast path is ordinary finite-field NO_TRACER DRL. During symbolic
preprocessing the basis is unchanged: row materialization inserts into the
secondary monomial table. New basis elements are added after the phase, so the
next phase rebuilds its index from the new active list.

Memory and profiling
--------------------
Each table slot is8 bytes. Capacity is a power of two at least twice the active
head count, with a minimum of16 slots. At3829 active heads, the table has8192
slots and occupies65536 bytes (64KiB). It grows only with the active basis size,
not with the number of queried monomials. Per-query scratch is proportional to
the number of variables and resides on the stack. No full query cache is used.

At safe boundaries the log reports:
  lookup_seconds, materialize_seconds, prepare_seconds;
  indexed_queries, fallback_queries, divisor_candidates;
  scanned_entries and avoided_entries;
  table_bytes, max_enumeration_product and product_overflows;
  hash-table probes and complete head-equality tests;
  materialized rows/terms and audit-query count.

All timing uses CLOCK_MONOTONIC. The audit binary additionally performs the
original scan for EVERY query and must not be used for performance measurements.
The index-off production mode provides a directly comparable scan baseline.

Validation
----------
Ten complete systems with index on, index off and the audit build matched the
frozen OpenMP driver and independent SymPy. Tests cover37,101,1009,65537,
1073741827; ordinary order and both tested block orders; nonreduced, unit,
positive-dimensional and degree-fall cases. Every matrix-round tuple matched.
The audit build checked every answer against the original first-divisor loop.

Twelve native-state tests covered baseline->index, index->baseline and
index->index. All complete bases and matrix-round sequences matched; each saved
checkpoint row independently reduced to0 in the original ideal. The saved pair
queue was restored normally, without initial pair regeneration.

A separate860-query semantic fixture used3000 degree3 leading heads in38
variables and600 degree6 queries. It replaced354867 ordered scan visits with
34582 enumerated divisor candidates and33828 occupied hash probes, while checking
every result against direct divisibility and the upstream first-divisor loop.
It also forced every head hash to the same value, reordered list positions,
included duplicate heads, checked the256-product limit and unsupported-mode
fallback. These are synthetic correctness/counter tests, not target timing.
