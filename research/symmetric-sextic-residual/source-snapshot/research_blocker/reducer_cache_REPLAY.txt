The serial and OpenMP sources, binaries and source manifests remain unchanged.
The new build uses the same native state ABI and retains their I/O cache handling,
thread option and safety-boundary checkpoints. The reducer cache itself is not
serialized: it starts cold on process restart, while the actual pair queue is
restored normally. Cold cache state cannot cause replay of consumed pairs.

Control and profiling
---------------------
The cache is enabled by default. --reducer-cache 0 disables it but retains the
separate CLOCK_MONOTONIC measurements and counters. All existing native driver
arguments remain available, including --threads and --resume-state.

Each completed symbolic phase reports, at the next safe boundary:
  * reducer lookup time;
  * row multiplication/hash-materialization time;
  * cache preparation time;
  * positive and negative hits, actual scanned basis entries, avoided entries;
  * allocated cache bytes;
  * materialized row/term counts and snapshot transition counts.

Materialization time wraps multiplied_poly_to_matrix_row and its small adjacent
setup. Lookup time covers the full cache/linear-search decision. The unmodified
symbol_rtime includes both phases, so it does not establish which one dominates.
The audit binary also runs the upstream reference lookup for every query; its
lookup timing is deliberately unsuitable as a performance benchmark.

Memory bound
------------
The direct-mapped cache has exactly262144 slots. Each slot stores a12-byte entry
and a full uint16 exponent key of native exponent-vector length evl. Ordinary
38-variable DRL has evl39, so the fixed cache allocation is:

  262144 * (12 + 2*39) = 23592960 bytes = 22.5MiB.

Small auxiliary snapshots and active-index maps grow with the number of basis
rows, rounded to powers of two. The reported cache_bytes includes those actual
allocation capacities. It is an allocated-byte count, not process RSS. The
number of monomial-cache entries does not grow with the computation. Collisions
evict entries rather than allocate more storage.

Why the first divisor is preserved
----------------------------------
The upstream symbolic lookup scans the ordered active leading-monomial list
and selects its first divisor of the query monomial. A positive cache entry
stores that winner's basis index and the complete query exponent vector.

Before each symbolic phase the implementation examines the current ordered
active list. It verifies active row indices, their strict increasing order,
and every surviving leading exponent vector. A transition may retain positive
entries only if it is exactly deletions from the previous list, followed by
fresh appended indices. New indices must be at least the previous basis load;
the load must not shrink. Any reused index, reordered list, changed surviving
head or other failed condition clears the relevant generation or disables the
cache for that phase. Invalid ordering falls back to the original linear lookup.

Suppose a cached first divisor survives such a checked transition. Every earlier
surviving old head was already a non-divisor of that same query. Every appended
head occurs after the surviving winner. Thus it remains the first divisor. A
removed winner is absent from the current active-index map and cannot hit.
The fresh-index and non-shrinking checks prevent a removed identity from later
being mistaken for a different reused row. This invariant is transitive across
successive checked phases.

A negative answer remains valid under deletions, but additions might introduce
a divisor. Therefore every addition invalidates negative entries. A changed
head or failed structural transition invalidates both kinds as needed.

The full exponent vector is compared before any hit is accepted; a hash match
alone proves nothing. A positive hit also rechecks current active status and
actual componentwise leading-monomial divisibility and reconstructs the exact
multiplier. A failed check falls back to a full first-divisor scan. The basis
is unchanged during the ordinary symbolic phase; row materialization adds to
the secondary monomial table, not to the basis.

The optimization is enabled only for ordinary finite-field NO_TRACER,
signature-free, non-final symbolic preprocessing. The other paths retain linear
lookup. Final reduction does not reuse this cache. No undocumented pointer or
monomial-hash identity is treated as a certificate of divisibility.

Validation completed
--------------------
Ten complete systems over37,101,1009,65537,1073741827, including ordinary and
both tested block orders, matched the frozen OpenMP implementation and independent
SymPy with cache on, cache off, and the shadow-audit binary. Every matrix-round
tuple also matched. The audit binary compared EVERY answer with an independent
copy of the original upstream first-divisor control flow.

Twelve native-state tests covered baseline->cache, cache->baseline and
cache->cache. Complete bases and matrix-round sequences matched the references;
every saved checkpoint row reduced independently to0 in the original ideal.

The aggregate complete-system fixtures made417 lookup queries. They recorded
48 positive and44 negative hits, reducing inspected basis entries from2208 to1683
(525 avoided). This is a small-fixture counter result, not a target performance
estimate. The off/on inspection counts reconciled exactly.

A separate502-query C semantic fixture forced identical hash values for all
queries and tested append, deletion of the winner, deletion of another row,
head change, reorder, basis-load shrink and index reuse. It checked answers
against a direct exponent-divisibility oracle and the original control flow.

------------

complete the target quotient, compute a trace, prove zero-dimensionality, or
supply the protected certificate. Every unfinished checkpoint remains incomplete.
